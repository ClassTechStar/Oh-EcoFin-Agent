# 1. 项目概述

## 1.1 项目定位与成功标准

本项目的第一身份是**大学 AI 课程作业**，因此成功标准不是"产品可用"，而是三件事：

1. **概念落地**：把"LLM 工具调用智能体 + 多空辩论 + 决策记忆"这些前沿机制（TradingAgents 一系）在 A 股场景完整跑通，能现场演示；
2. **实验评估**：消融矩阵 A–E + 20 个标准任务 + 性能红线 before/after 对照，用数据说话；
3. **报告质量**：架构图、消融表、衰减曲线、性能对照、局限性分析一应俱全。

由此推导的**核心工程原则：砍功能保实验**——一切与评估无关的炫技功能（用户系统、云数据库、分钟级回测、自动交易）一律不做；进度落后时按第 16 章"保险丝"顺序裁剪。

## 1.2 三大功能与演示主线

| 功能 | 内容 | 答辩演示中的角色 |
|---|---|---|
| 智能投研 | 单股四维分析 / 2–5 股对比（含相关性矩阵）/ 新闻情绪汇总（默认限 24h）/ 多空辩论式综合研判 / 决策记忆与复盘 | **可信主线**：数字溯源 + 辩论过程 + "记得上次的错误" |
| 智能投顾 | 对话式风险测评（5 题，上下文感知追问）→ Markowitz 均值-方差优化（Ledoit-Wolf）→ 合规审查链 → 有效前沿富组件图 | **体验主线**：手机现场对话式测评（ask_user 挂起机制） |
| 量化分析 | Backtrader 双均线回测（A股规则完整建模）+ Walk-forward 滚动验证（2 年训练 → 6 个月样本外 → 滚动 4 折）+ 多因子选股（四因子 + IC 验证） | **过拟合证据**：逐折衰减曲线 |

主战场 **A 股**：国产数据源（AKShare/东财）对 A 股支持最好，且"国产模型 + 国产数据 + A 股 + 国产新闻源"叙事完全自洽。

## 1.3 核心设计思想（四条铁律）

1. **数据必须来自工具**：模型凭记忆输出数字即视为幻觉。该命题不做口号，由消融实验 C 组（无工具直出）量化验证——无工具组的数字准确率预期显著低于基线，这是课程报告里最有说服力的一张表；
2. **每个数字可溯源**：报告数字强制携带编号出处（如 `[3] 行情快照@14:32:05`），评估脚本将报告数字与工具原始返回自动比对，**幻觉率可自动度量**；
3. **重大决策需辩论**：多空研究员基于同一份数据辩论，风控经理复议数据支撑度（借鉴 TradingAgents 核心机制：analyst → bull/bear → risk review → synthesis）；
4. **决策有记忆有反思**：每次投研决策（标的/结论/当时数据快照）写 SQLite 日志，T+N 后自动结算盈亏生成反思，历史教训注入后续分析——多轮自主智能体能力的直观展示。

## 1.4 参考项目与借鉴原则

详见附录 F 对照表。原则：**只借鉴机制，不复制代码**。六个关键借鉴点：

| multi-agent-robo-advisor（0xzhang-888） | 投顾合规审查链（适当性管理逻辑） |

## 1.5 交付物清单

1. GitHub 仓库（含 CI、测试、README 复现步骤）；
2. 课程报告（架构图 / 消融矩阵 / 衰减曲线 / 性能对照 / 局限性分析，结构见第 18 章）；

# 3. 技术栈选型与淘汰对照

## 3.1 选型总表

| 层级 | 选型 | 关键理由 |
|---|---|---|
| 主力 LLM | **GLM-5.3-Flash** | 智谱 2026-08 发布；320B 总参/激活 18B；1M 上下文；Function Calling；输出 2.8 元/M tokens——主推理链路 |
| 备用 LLM | **DeepSeek-V4.1-Flash-1017** | API 名 `deepseek-flash`；缓存命中 0.02 元/M——辩论轮/摘要/标题等模板化调用降本 |
| 模型接入 | OpenAI 兼容格式统一网关 | 双模型一套 tools Schema，失败自动降级 |
| 行情数据 | **AKShare（东财接口）** | 全市场快照一次拉取；免费 |
| 信息搜索 | 博查 → 智谱 Web Search → DeepSeek Search | 三源熔断；博查带股票模态卡可与快照交叉验证 |
| 组合优化 | **PyPortfolioOpt** | Ledoit-Wolf 收缩协方差（手写最易翻车点） |
| 回测引擎 | **Backtrader** | 中文资料最丰富；A股规则适配方案多；事件驱动天然防未来函数 |
| 技术指标 | **pandas-ta** | 130+ 指标纯 Python，避开 TA-Lib Windows 编译坑 |
| 后端 | FastAPI + uvicorn + SQLite | SSE 流式；SQLite 单文件零运维 |
| 前端 | Vite + lightweight-charts + ECharts | K 线用 lightweight-charts（~45KB gzip）；统计图 ECharts 按需注册 |
| 桌面壳 | **pywebview（onedir 打包）** | 冷启动 <2s；排除 Electron（重）、Tauri（Rust 成本不划算） |
| 移动壳 | **Capacitor → APK** | 复用同一前端做响应式适配 |

## 3.2 淘汰项对照（写入课程报告"技术选型"一节，体现决策深度）

| 候选 | 淘汰理由 |
|---|---|
| Electron | 桌面包 >150MB，冷启动 >3s，对课程演示是负资产 |
| Tauri | 产物小但 Rust 工具链学习成本与 12 周工期不匹配 |
| Qlib | 面向生产级因子平台，过重；留作"展望"章节的边界参照 |
| vectorbt | Windows 安装（numba/LLVM）坑多，答辩前夜翻车风险高 |
| TA-Lib | Windows 无 C 编译器装不上；pandas-ta 全替代 |
| Streamlit（v1.0 旧方案） | 无法承载 SSE 富组件、多端分发与 300KB bundle 红线 |
| 手写协方差矩阵 | Ledoit-Wolf 收缩是教科书级正确做法，手写必翻车 |

## 3.3 版本锁定策略

`requirements.lock.txt` 锁死全部依赖（含 AKShare——其接口列名随版本漂移，**必须锁**）；CI 与答辩机用同一份 lock 复现安装。升级依赖 = 单独 PR + 全量测试，绝不顺手升级。

# 4. 智能体引擎（模块 1）

**职责边界**：统一模型接入、ReAct 循环、参数沙箱、结果压缩、结构化输出、ask_user 挂起、辩论编排、决策记忆。不含任何具体金融逻辑（金融逻辑全部在工具层）。

## 4.1 LLMGateway：双模型统一网关

**深度优化点：**

1. **tier 路由策略**（成本第一道闸）：
   - `primary`（GLM-5.3-Flash）：ReAct 主循环、最终研判报告、投顾合规判断；
   - `economy`（deepseek-flash）：辩论轮、摘要、会话标题、反思文本——这些 prompt 模板化程度高，DeepSeek 缓存命中 0.02 元/M，成本近乎为零；
2. **失败降级链**：primary 超时(60s)/429/5xx → 自动切 economy 重试 1 次 → 仍失败则向 SSE 发 `error` 事件（可恢复类），**绝不静默吞错**；
3. **成本计量**：每次调用的 usage（prompt/completion tokens，缓存命中标记）写入 `llm_calls` 表，网关内做日累计；达到 `DAILY_COST_CAP`（默认 ¥20）触发**成本熔断**：拒绝新调用并提示（答辩前夜的超支保险丝）；
4. **OpenAI 兼容格式适配差异**：GLM/DeepSeek 的 `tool_calls[].function.arguments` 是 JSON **字符串**（非对象），网关统一 `json.loads` 容错（尾部空白/非法 JSON 捕获后交沙箱拒绝路径）；
5. **流式优先**：所有调用 `stream=True`，delta 聚合与思考通道透传一次实现，两模型复用。

```python
# backend/engine/gateway.py（骨架）
class LLMGateway:
    TIERS = {"primary": "glm-5.3-flash", "economy": "deepseek-flash"}

    def __init__(self, cfg, cost_ledger):
        self.clients = {t: AsyncOpenAI(base_url=..., api_key=...)
                        for t, m in self.TIERS.items()}
        self.cost_ledger = cost_ledger          # 日成本熔断器

    async def chat(self, messages, tools=None, tier="primary", *,
                   stream_cb=None, timeout=60) -> LLMResult:
        tier = self.cost_ledger.guard(tier)      # 超日上限 → raise CostFuseOpen
        try:
            return await self._call(tier, messages, tools, stream_cb, timeout)
        except (TimeoutError, RateLimit, APIError) as e:
            if tier == "primary":                # 降级链：仅 primary 降级
                return await self._call("economy", messages, tools, stream_cb, timeout)
            raise
```

## 4.2 工具注册与参数沙箱

每个工具 = `ToolSpec`；参数用 **pydantic 模型声明**，JSON Schema 自动生成给模型看（两模型共用一份）：

```python
@dataclass
class ToolSpec:
    name: str
    description: str
    params: type[BaseModel]        # pydantic 模型 = 白名单 + 类型 + 范围
    handler: Callable[..., Awaitable[dict]]
    compressor: str = "raw"        # kline | snapshot | news | raw
    parallel_safe: bool = True      # 快照读类可并行；搜索类串行防限速

class ToolRegistry:
    def schemas(self) -> list[dict]: ...        # OpenAI tools 格式
    async def execute(self, name: str, raw_args: str) -> dict:
        try:
            args = TOOL_PARAMS[name].model_validate_json(raw_args)
        except ValidationError as e:
            return {"ok": False, "error": f"参数校验失败: {e}",
                    "hint": "请对照工具说明修正参数后重试"}
        return await TOOL_HANDLER[name](**args.model_dump())
```

**沙箱语义**：违例参数不抛异常，而是**作为工具结果返回错误提示**——模型收到错误后通常一轮内自纠（实测国产模型容错良好）；同一调用失败自动重试 **1 次**为上限，再失败标记该工具本轮不可用。参数白名单还承担**类型与范围钳制**（如 `days ∈ [30, 500]`、`symbols 数量 ≤ 5`）。

## 4.3 ReAct 主循环（四重优化）

```python
# backend/engine/react.py（骨架）
MAX_ROUNDS = 12

async def run(task: ChatTask) -> AsyncIterator[Event]:
    for round_no in range(MAX_ROUNDS):
        resp = await gw.chat(msgs, tools=registry.schemas(), stream_cb=...)
        if resp.tool_calls:
            calls = [tc for tc in resp.tool_calls if tc.parallel_safe]
            results = await asyncio.gather(*[
                registry.execute(tc.name, tc.arguments) for tc in calls],
                return_exceptions=True)                    # ① 并行工具调用
            for tc, res in zip(calls, results):
                compact = Compactor.pack(tc.name, res)    # ② 结果压缩器
                msgs.append(tool_msg(tc, compact))
        elif resp.ask_user:                               # ③ ask_user 挂起
            yield ask_user_event(resp.ask_user)
            answer = await resume_queue.get()             # 用户点选后注入
            msgs.append(user_msg(answer))
        else:
            report = await submit_report(resp)            # ④ 结构化输出
            yield done_event(report)
            return
    yield error_event("轮次上限", recoverable=False)
```

**四重优化明细：**

| # | 优化 | 实现 | 预期收益 |
|---|---|---|---|
| ① | 并行工具调用 | 模型一次返回多个 `tool_calls` → `asyncio.gather` 并发执行 | 3 股对比端到端 ~8s → **~4s**（红线 <4s） |
| ② | 结果压缩器 | 见 4.4，K 线/快照进上下文前降维为统计量 | 上下文 token **-40%**（消融 E 组量化） |
| ③ | 参数沙箱 | 见 4.2 | 幻觉参数零副作用 |
| ④ | 结构化输出 | 最终报告**以工具调用形式提交**（`submit_research_report` 工具，入参即报告 Schema）——用 Function Calling 强约束 JSON，比 `response_format` 对双模型兼容性更稳 | 前端精确渲染富组件；Schema 违例自动带错误重试 1 次 |

**思考过程透传**：GLM/DeepSeek 的 `reasoning_content` 增量单独走 `thinking_delta` 事件，前端折叠展示——"看得见的推理"是答辩演示的重要素材。

## 4.4 结果压缩器（token 经济学）

| 工具返回 | 压缩策略 | 目标 |
|---|---|---|
| `get_kline`（500 根 OHLCV） | → 趋势方向、区间涨跌幅、年化波动、20/60 日均线距离、近 5 支撑/阻力位、量能变化摘要 | ≤ 300 tokens |

## 4.5 ask_user 挂起机制（特色亮点）

```text
引擎收到 ask_risk_question 工具调用
```

# 5. 数据服务（模块 2）

**职责边界**：对上层提供"永远可用、永远新鲜度可知"的行情读取接口；对下层消化 AKShare 的一切不稳定性（反爬/限速/列名漂移/停牌脏数据）。

## 5.1 全市场快照缓存（数据层地基）

```python
class SnapshotService:            # 后台任务，进程生命周期常驻
    async def loop(self):
        while True:
            interval = 60 if self._in_trading_hours(now) else 1800
            if not self._is_trade_date(now):     # 节假日/周末感知
                interval = 1800
            try:
                df = await self._fetch_spot()     # 东财全市场快照，1 次网络调用
                self._swap(df)                    # 原子替换（见下）
                await self._precompute_watchlist()
            except Exception:
                await self._backoff()             # 指数退避 1s→2s→…→60s 封顶
            await asyncio.sleep(interval)
```

**深度优化设计：**

1. **网络调用量恒定**：盘中无论多少用户/多少工具调用，出站始终 = 每 60s 1 次快照请求——**从架构上规避反爬**（不是靠 UA 伪装，而是靠调用模式像正常人）；
2. **原子替换无锁读**：新 df 构建完成后整体替换引用（Python 引用赋值原子），读侧 `self._df.loc[symbol]` 永不加锁——工具 <50ms 的前提；内存 footprint ≈ 5000 行 × 20 列 DataFrame，约 1MB 量级，可接受；
3. **降频语义**：盘后 30 分钟一次；交易日历（`ak.tool_trade_date_hist_sina`）缓存到本地 JSON，跨年自动补抓；
4. **东财→新浪降级**：连续 3 次失败自动切 `ak.stock_zh_a_spot()`（新浪源，列名不同 → 映射层归一），恢复后切回东财；
5. **盘后回放**：非交易时段返回最后一份快照，并强制 `is_stale=True`——诚实降级而非假装实时。

## 5.2 预计算指标层

关注池（用户查询过的标的 ∪ 决策日志标的 ∪ 演示白名单）在快照刷新后增量计算：MA5/10/20/60、RSI14、MACD(12,26,9)、量比、换手。工具调用时**零计算零等待**——pandas-ta 只在后台线程跑，工具热路径上没有任何指标计算。

## 5.4 数据质检与新鲜度协议

| 检查 | 规则 | 处置 |
|---|---|---|
| 停牌 | 成交量为 0 或快照行缺失 | 返回 `{ok: False, reason: "停牌"}`，**不进模型** |

# 6. 信息搜索（模块 3）

**三源熔断链**：博查（带股票模态卡，可与快照交叉验证）→ 智谱 Web Search → DeepSeek Search。

## 6.1 深度优化设计

1. **熔断器**：单源连续 3 次失败 → 熔断 5 分钟（半开探测恢复）；三源全断 → 返回缓存 + `is_stale` 并明示"信息源暂不可用"；
2. **TTL 缓存**：新闻类查询缓存 30 分钟（键 = 规范化 query + 标的），个股公告 10 分钟——投研任务在一次会话内重复查询同一标的是常态，缓存命中即省钱省延迟；
3. **去重排序**：标题 hash 去重 → 按 相关性 × 时效衰减（24h 内 ×1.0，48h ×0.7，更早 ×0.4）复合排序 → **默认只取 24h 内**，不足 3 条放宽到 72h 并打标；
4. **模态卡交叉验证**：博查返回的股价模态卡与本地快照比对，偏差 >1% 时以本地快照为准并记一条"外部数据不一致"日志（答辩可演示"我们不盲信搜索结果"）；
5. **情绪预聚合**：搜索结果在进 LLM 前先做规则级情绪标签（标题关键词词典 + 股吧情绪词表），LLM 只做聚合判断——token 成本再降一档。

## 6.2 验收

搜索链路可用性 >99%（以周记日志统计：缓存命中不计入失败）；熔断状态转换单测；去重后 10 条→≤6 条的样本固化 golden。

## 8.2 Markowitz 优化（PyPortfolioOpt）

```python
mu  = expected_returns.mean_historical_return(prices)      # 注意：吃价格 DataFrame，不是收益率！
S   = risk_models.CovarianceMatrix.ledoit_wolf(prices)     # 收缩协方差（防小样本病态）
ef  = EfficientFrontier(mu, S, weight_bounds=(0, cap))     # cap = 风险等级权益上限
ef.add_constraint(lambda w: w[single_idx] <= single_cap)    # 单一资产上限（8.1 表）
w   = ef.max_sharpe() if level >= R4 else ef.min_volatility()
```

**有效前沿缓存**：键 =（标的池 hash + 交易日 + 风险档），当日重复对话零重算（PyPortfolioOpt 全前沿求解 ~2s，缓存后 <50ms 复用）；前沿数据随 chart 事件下发，**当前配置点高亮标注于前沿曲线上**（答辩演示图）。

## 8.3 合规审查链（适当性管理逻辑的工程化）

```python
def compliance_check(portfolio, level) -> list[Violation]:
```

审查是**确定性代码**而非 LLM 判断（LLM 只解释结果）——合规规则的执行不依赖模型自觉，这是答辩 Q&A 的标准答案。

## 8.4 验收

测评 6 任务完成率；同一用户重复对话 → 追问措辞不同而等级判定一致（措辞/计分解耦的单测）；合规链全规则单测 + 违规注入用例 3 个（占比超限/单一超限/缺声明）。

# 9. 量化分析（模块 6）

## 9.1 A 股交易规则完整建模（Backtrader）

| 规则 | 数值/语义 | Backtrader 实现 |
|---|---|---|
| 佣金 | 万 2.5，最低 5 元 | `CommInfoBase(commission=0.00025, mult=1)` + `getcommission` 中 `max(fee, 5)` |
| 印花税 | 0.05%，**仅卖出** | 自定义 scheme：`sell` 分支加 `0.0005 × 成交额`，买入不加 |
| T+1 | 当日买入不可当日卖出 | 策略层持仓账本：记录每笔买入的交易日，`next()` 中仅允许卖出"昨日及更早"的持仓 |
| 涨跌停 | 主板 ±10%（创业板/科创板 ±20%、ST ±5% 分档） | `next()` 开盘价较昨收触及 ±9.9%（按板块档）→ **跳过当日下单**（成交假设不成立） |
| 复权 | 回测一律**后复权**（`adjust="hfq"`） | 消除除权跳空的假信号/假亏损 |

**AKShare→Backtrader 数据适配**（列名中文→英文重映射，最常见的翻车点）：

```python
class AKShareData(bt.feeds.PandasData):
    params = (("datetime", None), ("open", "open"), ("high", "high"),
              ("low", "low"), ("close", "close"), ("volume", "volume"), ...)
```

**防未来函数铁律**（信号在 t 收盘计算，t+1 开盘成交）：`cheat_on_open=False`（默认）、指标信号统一 `.shift(1)` 校验、回测前跑"未来函数扫描器"（第 9.4 节）。

## 9.2 双均线策略（基准策略，服务演示）

参数网格：fast ∈ {5,10,20} × slow ∈ {20,60,120}（fast < slow 约束），全进全出，初始资金 100 万。它的任务不是赚钱，是**作为 Walk-forward 的载体**。

## 9.3 Walk-forward 滚动验证（过拟合的直观证据）

```python
folds = make_folds(daily, train=504, oos=126, step=126)   # 2 年训练 → 6 个月样本外 → 滚动 4 折
for f in folds:
    best_params, is_sharpe = grid_search(f.train)         # 样本内寻优（全参数网格）
    oos = backtest(f.oos, best_params)                     # 样本外一次性执行
    decay[f] = oos.sharpe / max(is_sharpe, 1e-9)          # 逐折衰减率
# 产出两条曲线：训练集夏普 vs 样本外夏普（分折并列柱状图）
```

**报告叙事**：样本内夏普动辄 2.0+，样本外 0.x 甚至为负，逐折衰减曲线 = "为什么不能直接用回测最优参数上实盘"的教科书答案——这是课程报告中**最有教学价值的一张图**。

## 9.4 多因子选股（数据驱动的因子有效性验证）

```python
横截面日期 t，样本 = 快照全市场（剔除停牌/次新<120日）
factors = {价值: EP(TTM), 质量: ROE, 动量: 120日收益率, 低波动: 60日std}
处理链:  MAD 去极值（|x-med|>3×MAD → clip）
        → Z 标准化（截面）
        → 等权合成 composite → Top20 组合
验证:    rank IC（Spearman，因子值 vs 未来20日收益）
        → IC 序列的 t 统计量（|t|>2 即显著）+ IC 衰减曲线（1/5/10/20/60 日）
```

**因子选择从拍脑袋变为数据驱动**：IC 表决定哪些因子进 composite、权重多少——答辩 Q&A"为什么是这四个因子"的答案就是这张 IC 表。

**未来函数扫描器**：因子计算只用 ≤t 数据、IC 评估的"未来收益"仅用于评估不进入信号——扫描器静态检查所有 `.shift(-`/`.rolling(`+未来列引用，CI 强制跑。

## 9.5 验收

样本外夏普**可复现**（固定数据窗口 + 固定参数网格 → 逐折数字 byte 级一致，golden 固化）；佣金/印花税/T+1/涨跌停四规则各有独立注入用例（构造极端行情验证税费生效）；未来函数扫描器零报警。

## 10.1 分层摘要（长会话成本 -70%）


# 11. API 与 SSE v2 富组件协议（模块 8）

## 11.1 事件协议表

| event | payload 关键字段 | 说明 |
|---|---|---|
| `message_delta` | `{text}` | 回复正文增量 |
| `thinking_delta` | `{text, model}` | GLM/DeepSeek 思考过程独立通道 |
| `tool_call` | `{id, name, status(start/success/error), args, result_digest, ms, cached}` | 前端渲染折叠时间线 |
| `chart` | `{id, kind(kline/eff_frontier/heatmap/radar/decay), title, data, cite:[n]}` | 富组件数据体 |
| `ask_user` | `{qid, question, options, context}` | 挂起式提问 |
| `done` | `{usage, cost_breakdown, rounds, tool_stats}` | 终态含成本 |
| `error` | `{code, message, recoverable}` | 可恢复错误前端展示重试按钮 |
| `ping` | — | 15s 心跳 |

## 11.2 断线重连重放

- 每事件**递增整数 id**（会话级单调，SQLite 持久）；
- 重连带 `Last-Event-ID` → 服务端从环形缓冲（内存 500 条 + 落库兜底）重放其后全部事件；
- **移动端网络切换（WiFi↔蜂窝）不丢流**——答辩现场手机演示的底层保险；
- 响应头 `X-Accel-Buffering: no`、`Cache-Control: no-store`（防中间层缓冲截流，pywebview 的 Edge WebView2 内核直连不受影响）。

## 11.3 前端按 kind 路由渲染

`kline` → lightweight-charts；`eff_frontier`/`heatmap`/`radar`/`decay` → ECharts（按需注册）；`ask_user` → 选项卡片组。图表数据体带 `cite:[n]`，与正文溯源编号联动。

## 11.4 验收

断流注入测试（proxy 随机断连 10 次）消息零丢失；事件 id 严格递增单测；ping/心跳在弱网下保活。

# 13. 安全与合规（模块 10）

## 13.1 密钥管理（keyring 三级读取）

```text
读取优先级：环境变量 FINAGENT_GLM_KEY（CI/测试）
```

## 13.2 其余安全设计

- **日志脱敏**：logging Filter 正则掩蔽 `api_key/Authorization/手机号`；工具原始返回落库前同规则；
- **绑定纪律**：默认 `127.0.0.1`；局域网模式需 UI 显式开启 + 随机 token；**永不默认 0.0.0.0**；
- **免责声明三层**：页面 footer 常驻 + 每份报告 `risk_disclosure` 字段（Schema 强制）+ API 响应体附带（文案见附录 C.6）；

- SQLite 注入面：全部 ORM 参数化（sqlalchemy 或手写占位符），无字符串拼接 SQL。

## 13.3 验收

密钥三级读取优先级单测；脱敏 golden 样例（含伪造 key/手机号文本）；免责声明存在性扫描（全部报告出参）；局域网未开 token 时外部连接 403。
